개발은 코드를 작성하는 일만으로 끝나지 않는다. 요구사항을 어떻게 나누고, 변경 이력을 어떻게 관리하고, 팀원과 어떻게 리뷰하고 배포할지까지 포함한다. Agile은 일하는 방식이고, Git은 변경 이력을 관리하는 도구이며, GitHub와 GitLab은 협업 플랫폼이다.

## Agile과 Waterfall

- Waterfall은 요구사항 분석, 설계, 구현, 테스트, 배포가 순차적으로 진행되는 방식이다.

- Agile은 짧은 주기로 계획, 구현, 피드백, 개선을 반복하는 방식이다.

- 변경이 잦거나 사용자 피드백이 중요한 프로젝트에서는 Agile 방식이 더 유연하다.

- Agile은 문서를 없애는 방식이 아니라, 필요한 문서를 가볍게 유지하면서 동작하는 결과물을 빠르게 검증하는 방식에 가깝다.

## Git

- Git은 분산 버전관리 시스템이다.

- 각 개발자는 로컬 저장소에서 커밋과 브랜치 작업을 할 수 있고, 원격 저장소와 동기화해 협업한다.

- 브랜치를 활용하면 기능 개발, 버그 수정, 실험 작업을 분리하고 나중에 병합할 수 있다.

## GitHub

- GitHub는 Git 저장소 호스팅과 협업 기능을 제공하는 플랫폼이다.

- Pull Request, Issue, Actions, Packages, Projects 같은 기능을 통해 코드 리뷰와 자동화를 지원한다.

- 오픈소스 생태계와 공개 프로젝트 협업에 강점이 있다.

## GitLab

- GitLab은 Git 저장소, 이슈, CI/CD, 보안 기능을 통합한 DevOps 플랫폼 성격이 강하다.

- 자체 호스팅 옵션이 있어 기업 내부 환경에서 전체 개발 흐름을 한 플랫폼으로 관리하기 좋다.

- Merge Request와 GitLab CI를 통해 코드 변경과 배포 파이프라인을 연결할 수 있다.

## 협업 흐름

- 작업 단위를 이슈로 나누고, 브랜치를 만들어 개발한다.

- 변경 사항은 Pull Request 또는 Merge Request로 리뷰한다.

- CI 테스트를 통과한 뒤 main 브랜치에 병합하고, 배포 파이프라인으로 연결한다.

## 정리

Agile은 팀의 반복 개선 방식, Git은 코드 변경 이력 관리, GitHub와 GitLab은 협업과 자동화 플랫폼이다. 이 세 영역을 함께 이해하면 개발 프로세스가 단순한 코드 작성에서 운영 가능한 소프트웨어 전달 흐름으로 확장된다.
